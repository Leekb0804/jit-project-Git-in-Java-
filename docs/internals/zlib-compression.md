# 📦 데이터 압축과 저장 (zlib)

JIT(Java Git) 프로젝트는 Git의 표준을 따르기 위해 **zlib**을 사용하여 객체를 압축 저장합니다.

## 1. zlib이란?
**zlib**은 데이터 압축을 위한 표준 라이브러리이자 압축 포맷입니다.
*   **무손실 압축 (Lossless):** 압축을 풀었을 때 원본 데이터가 1비트도 손실되지 않고 완벽하게 복구됩니다.
*   **DEFLATE 알고리즘:** 내부적으로 LZ77(중복 문자열 제거)과 Huffman Coding(빈도 기반 압축)을 조합하여 높은 압축 효율을 제공합니다.
*   **표준성:** PNG 이미지, HTTP 프로토콜, 그리고 **Git** 등 수많은 시스템에서 표준으로 사용됩니다.

## 2. 왜 Git은 zlib을 사용하는가?
Git이 모든 객체(Blob, Tree, Commit)를 파일로 저장할 때 zlib으로 압축하는 이유는 크게 세 가지입니다.

### ① 저장 공간 효율성 (Disk Space)
소스 코드는 텍스트 파일이며, 프로그래밍 언어 특성상 `public`, `class`, `return` 같은 키워드가 매우 빈번하게 반복됩니다. 이러한 텍스트 데이터는 압축 효율이 매우 높아, 저장소 용량을 획기적으로 줄일 수 있습니다.

### ② 데이터 무결성 및 보호 (Integrity & Obfuscation)
`.git/objects/` 내부에 저장된 파일은 텍스트가 아닌 바이너리 형태로 저장됩니다.
*   사용자가 실수로 편집기에서 객체 파일을 열어 수정하는 것을 방지합니다.
*   단순 텍스트 파일이 아닌, Git이 관리하는 '객체'임을 명확히 합니다.

### ③ I/O 성능 최적화
디스크 I/O는 CPU 연산보다 훨씬 느립니다. 대용량 텍스트 파일을 그대로 읽고 쓰는 것보다, 압축된 작은 데이터를 읽어서 메모리에서 빠르게 압축을 해제하는 것이 전체적인 성능 면에서 유리할 수 있습니다.

### ④ 데이터 무결성 체크 (Adler-32 Checksum)
Zlib 포맷 내부에는 **Adler-32**라는 체크섬(Checksum)이 포함되어 있습니다.
*   **체크섬(Checksum)이란?** 데이터가 변조되지 않았는지 확인하기 위해 원본 데이터로부터 계산해 낸 고유한 숫자(지문)입니다.
*   **검증 원리:**
    1.  **저장 시:** 원본 데이터의 Adler-32 값을 계산하여, 압축된 데이터의 **맨 끝**에 함께 저장합니다.
    2.  **읽기 시:** 압축을 풀면서 나온 데이터로 다시 Adler-32 값을 계산합니다.
    3.  **비교:** `저장되어 있던 값` vs `방금 계산한 값`이 다르면, 데이터가 손상된 것으로 간주하고 즉시 에러(`ZipException`)를 발생시킵니다.

## 3. 다른 압축 알고리즘과의 비교 및 선택 이유

### 🔍 주요 압축 알고리즘 비교

| 알고리즘 | 특징 | 장점 | 단점 |
| :--- | :--- | :--- | :--- |
| **Zlib (DEFLATE)** | LZ77 + Huffman Coding | **속도와 압축률의 균형이 우수함**, 표준 라이브러리 지원 강력 | LZ4보다 느림, XZ보다 압축률 낮음 |
| **GZIP** | Zlib과 동일한 DEFLATE 사용 | 파일 단위 압축에 주로 사용 (헤더에 메타데이터 포함) | Zlib보다 헤더가 커서 작은 객체 저장 시 오버헤드 발생 |
| **LZ4** | 속도 중심 | **압도적으로 빠른 속도** (실시간 처리에 적합) | 압축률이 낮음 |
| **XZ (LZMA)** | 압축률 중심 | **매우 높은 압축률** | 압축/해제 속도가 매우 느림 |

### ✅ 왜 JIT는 Zlib을 선택했는가?

1.  **Git 생태계와의 호환성 (Interoperability):** 만약 우리가 더 빠른 LZ4를 사용한다면, `jit`으로 생성한 저장소를 **오리지널 Git(CLI), GitHub, SourceTree** 등이 전혀 읽을 수 없게 됩니다. "Git 구현체"를 만든다는 것은 기존 Git 도구들과 완벽하게 섞여서 동작할 수 있어야 함을 의미합니다.
2.  **적절한 균형:** 소스 코드 관리 시스템(VCS)은 저장 공간 절약(압축률)과 빠른 커밋/체크아웃(속도) 두 마리 토끼를 다 잡아야 합니다. Zlib은 이 두 가지 요구사항 사이에서 가장 이상적인 균형을 제공합니다.
3.  **Java 표준 지원:** 외부 의존성 없이 `java.util.zip` 패키지만으로 완벽하게 구현할 수 있어 프로젝트의 복잡도를 낮출 수 있습니다.

## 4. JIT에서의 데이터 저장 흐름
JIT 프로젝트에서 객체가 저장되는 과정은 다음과 같습니다.

1.  **데이터 준비:** 객체의 타입, 크기, 내용을 합쳐 헤더를 생성합니다.
    *   Format: `blob 12\0Hello World!`
2.  **ID 생성 (SHA-1):** **압축 전**의 데이터를 기준으로 해시(ID)를 계산합니다.
    *   ID: `5e1c309...`
3.  **압축 (zlib):** 데이터를 zlib으로 압축하여 바이너리 데이터로 변환합니다.
4.  **파일 저장:** 계산된 ID를 경로로 사용하여 압축된 데이터를 저장합니다.
    *   Path: `.git/objects/5e/1c309...`

## 5. Java 구현 (java.util.zip)
Java에서는 별도의 라이브러리 설치 없이 기본 내장된 패키지를 통해 zlib을 지원합니다.
*   **압축:** `java.util.zip.Deflater` / `DeflaterOutputStream`
*   **해제:** `java.util.zip.Inflater` / `InflaterOutputStream`
